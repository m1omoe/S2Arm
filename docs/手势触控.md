# 手势触控：不画按键，滑动推摇杆、点按分区出按键

状态：候选实现，代码已落地（`ios/vpad.m` / `vpad_layout.{h,m}` / `vpad_settings.m`），待 CI 编译与真机验证；分区大小与位置未在真机上调过。与 F01 的关系：F01 管虚拟按键的矩形，本条是**第三条输入方案**，不改变任何按键几何。与[触屏直通](触屏直通.md)的关系：直通把手指交给游戏，本条把手指解释成手柄。

## 问题

两个已有方案各缺一半：

- 按键方案（默认布局 / 用户 JSON）满屏是按键和摇杆圈，画面被挡住一层；闲置透明度能压到 0，但按下时按键仍会亮起来，且手指必须落在键上。
- 触屏直通一个按键都没有，但它只发 `Hid.Touchscreen`、不发手柄——主流程靠摇杆和按键的游戏（《集合啦！动物森友会》这类）根本玩不了：移动、对话、采集全是手柄输入，游戏自带的触屏 UI 只管菜单和键盘。

缺的是一套「不画任何东西、又能出完整手柄输入」的方案。

## 三套方案

“触屏布局…”管理页第一组与齿轮菜单「按键布局」里并列（内置 id 都不落 JSON 文件，只记选择记录）：

| 项 | 屏幕上 | 数据面 |
|---|---|---|
| 默认布局 / 2D / 用户 JSON 方案 | 方案里的按键 + 浮动摇杆圈 | 只发 `Hid.Npads`；`Hid.Touchscreen` 恒 0 个触点 |
| 触屏直通（内置 id `touch`） | 一个按键都不画，也没有摇杆圈 | 只发 `Hid.Touchscreen`；不发布手柄 |
| 手势触控（内置 id `gesture`） | 一个按键都不画，摇杆圈也不画 | 只发 `Hid.Npads`；`Hid.Touchscreen` 恒 0 个触点 |

互斥规矩与直通文档里写的一样：手势方案若同时发触点，手指推摇杆 / 点 A 时会被游戏当成点按，属于纯误触，所以只发手柄。代价也一样：游戏自带的触屏 UI（哩数商店点选、打字键盘）在手势方案下点不到，要用时切直通或按键方案；切回照旧四指长按 1.5 秒开菜单（`ios/diag.m` 的识别器 `cancelsTouchesInView = NO`，不吃触摸，与本层并行）。

## 手势与分区

坐标相对安全区：x 按宽、y 按高，半径按安全区短边折算。判定顺序：按键分区（先命中先得）→ 十字键圆区 → 剩下的按左右半屏认领浮动摇杆。常量集中在 `ios/vpad.m` 的 `kGestureZones` 与 `kGestureDpad*`，改手感只改那一块。

| 手势 | 输入 |
|---|---|
| 左半屏空白处按下并拖动 | 左摇杆：落点当中心，拖 60 点推满（与按键方案的浮动摇杆同一套判定），松手回中 |
| 右半屏空白处按下并拖动 | 右摇杆（镜头），同上 |
| 点按 / 按住右下菱形区 | A（0.93, 0.58）最大区；B（0.85, 0.76）；X（0.85, 0.40）；Y（0.75, 0.58），半径 0.17–0.20 |
| 点按 / 按住上缘 | ZL（0.07, 0.15）大区、L（0.19, 0.15）、R（0.82, 0.15）、ZR（0.93, 0.15）；−（0.44, 0.09）、＋（0.56, 0.09） |
| 左下圆区内点按 / 滑动 | 十字键：圆心（0.165, 0.70）、半径 0.21，按角度出八方向（斜角同时两位），正中心一小圈（半径 0.2 倍）不算方向；滑出圆区保持最后方向 |
| 摇杆区点一下不拖（≤0.25 秒、≤10 点）抬手 | 按一下 LS / RS（与按键方案同一判定，走 pad.c 短按锁存） |
| 双击同侧半屏、第二下按住 | 按住 LS / RS |

按法要点：

- 分区按键按住不放就是按住（B 疾跑、长按 A），滑出区外也不松手，抬手才松——同实体按键。
- 多指各记各的（沿用 `_held` 的触点 → 输入映射）：左手推着摇杆、右手同时点 A / 按住 B 互不干扰，这是本方案的核心玩法。
- 没有视觉反馈：按下靠触感反馈确认（设置里开着时，新按下轻震一次，与按键方案同一条路）。

## 实现

`ios/vpad.m`

- `_gesture` 由 `reloadLayout` 按选择记录置位。激活时 `rebuildKeys` 返回空（一个按键视图都不建）、摇杆圈永不显示（`restStick` 与认领处都跳过显隐），`wake` 不做淡入淡出。
- `gestureDown` / `gestureMove` 是解释器：落点先过 `gestureHitAt`（分区表 + `gestureDpadDirsAt` 十字键圆区），命中记按键位或 `kDpadHeld + 方向位`；没命中按半屏认领浮动摇杆，复用 `_stick` / `_c` / `moveStick` 与点按、双击 LS / RS 的既有判定（`_downAt` / `_maxMove` / `_lastUp`）。
- 抬手走既有 `end:`：摇杆点按补一拍、回中、圈收起（本方案圈本来就不显示）；分区按键从 `_held` 移除即松开。全部状态最终经既有 `publish` → `s2a_pad_update(S2A_PAD_TOUCH, …)` 进 `runtime/src/pad.c` 的合并层，pad.c / InputPump / HID 一行未改。
- 接了实体手柄时本层保留（同直通）：`setInputEnabled` 不隐藏，手指与手柄仍是两条独立输入，合并层按既有规则取舍。
- 本方案没有可编辑的按键：齿轮菜单与四指菜单里的「编辑按键位置」禁用 / 不列，`beginEditing` 直接返回。

`ios/vpad_layout.{h,m}`

- 新增内置 id `gesture`（`S2AVPadLayoutGestureIdentifier`），并入 `+isBuiltinIdentifier:` 的统一判断：`layouts` 跳过同名文件、`selectedLayout` 返回 nil、`saveLayout` / `replaceLayout` 拒绝、 `selectIdentifier` 免读文件，四处与 `touch` 同处理。

`ios/vpad_settings.m`

- 第一组固定四行：默认布局 / 触屏直通 / 2D 布局 / 手势触控，之后才是用户方案；文案键 `vpad.layout.gesture`、`vpad.layout.gesture.note`、`vpad.layouts.gesture.note` 已补齐六个语言。

游戏库侧（`ios/vpad_shell.m`）不改：它只认 mine / default / touch，其余归 other，与 2D 布局同一待遇；手势方案没有按键可拖，库里的布局编辑不适用。

## 验证

- 未做：本地 Linux 环境编不了 iOS / Objective-C，第一次真编译是 CI 的 build-shell 流水线；真机手感（分区大小、误触率、推杆跟手）完全未验，分区常量是按默认布局的键位放大推的，第一次真机试玩后大概率要调。
- 待验清单：① 选「手势触控」后 host.log 打 `触屏布局：手势触控（不显示虚拟按键，滑动推摇杆、点按分区出按键）`，屏幕上无任何按键与摇杆圈；② 左手推杆移动、右手点 A 对话、按住 B 疾跑同时成立；③ 十字键上（工具环）与斜向滑动；④ 点一下摇杆区 = LS / RS、双击按住 = 按住 LS / RS；⑤ 四指长按 1.5 秒能开菜单切回；⑥ 游戏自带触屏 UI 点不到（预期内，与按键方案同）。

## 已知限制

- 分区靠落点，没有视觉锚点：靠手指记忆与触感反馈，熟练前容易按偏；A / B / X / Y 与十字键的位置只能整体调常量，不能逐个拖位（本方案没有编辑器）。
- 十字键圆区与左摇杆区重叠：圆区内一律先认十字键，想在左下推杆要落在圆区外。
- 右半屏的镜头摇杆与 ABXY 分区同理：落在分区里的触点出按键，不推镜头。
- ZL / ZR 按住锁定（按键方案的 2 秒锁定）在本方案照常生效（走同一份 publish 状态机），键上小锁看不见，锁定状态只能靠触感与游戏内表现判断。
